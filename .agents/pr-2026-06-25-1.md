# PR 2026-06-25-1: Streamable-HTTP transport + OIDC bearer-auth gate

## Status
QA: APPROVED

## Summary

Adds an optional Streamable-HTTP transport (`SCOUT_TRANSPORT=http`) alongside the existing
stdio transport, gated by `resolveTransportMode`/`resolveHttpPort` (src/transport.ts), plus
an OIDC bearer-token validation layer (src/auth/oidc.ts, src/auth/middleware.ts) using `jose`
for JWKS-based signature/issuer/audience/expiry verification of incoming `Authorization` headers
in HTTP mode.

## Test file review

**tests/oidc-auth.test.ts** — confirmed genuinely offline. Generates a local RS256 keypair via
`jose.generateKeyPair`, builds a `createLocalJWKSet` from the exported public JWK, signs test
tokens locally with `SignJWT`. Grepped the file for `fetch`/`http`/`https` — zero hits outside a
comment stating the offline design. No real OIDC provider or network call anywhere in the suite.

**tests/transport.test.ts** — `resolveTransportMode`/`resolveHttpPort` pure-function tests, no
network or process spawning; same offline characteristic confirmed by grep.

## Adversarial checks (all independently reproduced, not taken on claim)

1. **`SCOUT_TRANSPORT=websocket`** — clean exit, code 1, no stack trace, no silent fallback:
   `[scout-mcp] Invalid SCOUT_TRANSPORT="websocket" — expected "stdio" or "http".`
2. **Tampered signature** (flipped one char in the signature segment of a validly-signed token) —
   rejected: `Bearer token verification failed: signature verification failed`.
3. **`alg: none` unsigned token** (hand-built header/payload, empty signature segment) — rejected:
   `Bearer token verification failed: Unsupported "alg" value for a JSON Web Key Set`. Classic
   footgun is closed — `jose`'s `createLocalJWKSet`/`jwtVerify` never honors `alg: none`.
4. **Valid signature, wrong audience** — independently re-signed a token for `totally-different-audience`
   and verified rejection: `unexpected "aud" claim value`. Confirms the implementer's claim, not just
   trusting their test.
5. **stdio mode, no `SCOUT_TRANSPORT` set** — started with fake Scout creds; identical behavior to
   main: only the existing startup-auth warning printed, process stays alive on stdio, no new
   required env vars, no new errors introduced by this branch.
