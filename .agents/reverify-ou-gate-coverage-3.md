F13 LOW functional (behaviour note): notification_manage target=ou type=devicerelocation requires body.destinationOU (spec RelocationInformation); it normalises to `destinationou` (SPECIFIC_OU_KEY) so it is now refused when it names an OU other than the gated one, and dropped when it equals it. Previously it passed through UNGATED, so this is a safety gain but target=ou relocation to another OU is no longer possible via this tool (use the dedicated move tools). Document in README; non-blocking.
F14 LOW residual-accept: app_manage create scope=ou keeps body `id`/`path` (generic:false). openapi.json application schemas (CommonApplicationFields, Browser/Local/Rdp/Avd/Omnissa/Storefront, SharedRemoteAppFields) contain NO id/path/OU field (Name, DisplayName, Parameter, StartPage...). So the exception protects nothing real; an OU retarget through `id`/`path` is not a spec'd binding and the OU is carried by query id=<gated>. Cannot be an OU smuggle per spec; recommend flipping to generic:true (spec has no such app fields). scope=base body is unsanitised but global (no OU).
