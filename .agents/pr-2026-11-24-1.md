## Findings (none blocking)
1. MEDIUM `src/tools/elias.ts` `asArray()` (~l.140): a 200 whose body is not an array (error envelope, `{response:[...]}` wrapper, HTML-turned-object) becomes `[]`, so list tools report `total:0` as success. Repro: stub rawRequest -> `{error:"x"}`; `elias_container_list` returns total 0, no error. Fix: fail when the body is non-array/non-null, or add a `warning`.
2. MEDIUM `elias.ts` `elias_certificate_get signing=true`: any 404 (wrong/nonexistent containerId, ELIAS absent) is reported as `{signingCertificate:"none"}` and bypasses the wrap() capability message. A 404 therefore looks like success. Suggest: only map to "none" when the container is known to exist (e.g. confirm via container list or `requireCapability`), or return `status:"none-or-container-not-found"`.
3. LOW `elias.ts` SECRET_KEY_RE is an exact-name match: `privateKeyPem`, `clientSecret`, `apiKey`, `token`, `accessToken`, `keyData`, `pem` are NOT redacted (repro: `redactSecrets({privateKeyPem:'a'})`). `PrivateKey`/`Password` (case) and nested/array values are handled. Mitigated because most tools use `pick()`; `elias_health` and `elias_rights` return raw bodies. Also `-----BEGIN PGP PRIVATE KEY BLOCK-----` is not matched. Consider substring match (`/key|secret|token|passw|pfx|p12/i`).
4. LOW over-redaction: `\bPFX\b` redacts any string containing `.pfx` (e.g. cert `filename: "sign.pfx"` -> `[REDACTED]`), losing useful metadata.
5. LOW `src/compat/registry.ts` `advanced-file-entries.dependentTools` lists `config_get`,`config_update`, but the only consumer is `config_resolve` (grep `fileEntries` in src). Docs row/registry both drift from reality; no test checks non-ELIAS dependentTools exist. Fix registry to `['config_resolve']` and extend the dependentTools test to all capabilities.
6. LOW `detect.ts` `findVersionField`: returns the first nested `version`/`scoutVersion` that parses as YYMM anywhere in healthcheck/instances (e.g. a database "22.04" or "2012" would parse as a Scout version), reported with 'low' confidence only. Prefer a known path or the `scoutServer` subtree.
7. LOW `detect.ts` `detectCapabilities`: probes + version requests fire concurrently (up to ~9 requests) with no in-flight dedupe; two concurrent `health_check` calls after the 5-min TTL double the probes, and `ensureAuth` has no login mutex (parallel logins if the token just expired). A 200 non-JSON probe body throws in `res.json()` and is classed `unknown` rather than `available`.
8. LOW `config.ts`: in dry-run the config_update preflight still performs the ourights GET and can refuse (device_command/ou_manage skip it in dry-run). Inconsistent, not a safety issue.
9. LOW `rsop.ts` `parseAdvancedFileEntries`: zero-width stripping only on `Key`; `File`/`Section` with zero-width chars or differing case form separate fold entries. `.env.example`: comment appended on the same line as `SCOUT_ENABLE_PRIVATE_ENDPOINTS=false` (missing newline; dotenv parses fine, `source .env` would not).
