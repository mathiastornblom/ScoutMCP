## Blocking
B1 (C7). Absolute local path leaks into tool output. `EliasAuditError` message embeds the first 120 chars of the fs error, which contains the path (probe: `audit intent row could not be written (EACCES: permission denied, mkdir '/var/folders/.../sub')`). The pipeline returns `err.message` unsanitised as the `audit-write` refusal. C7 requires basenames only. Fix: map to `err.code` (EACCES/ENOSPC/EIO) and a fixed text, never `err.message`. Add a test asserting the refusal message contains no `/`.

B2 (C1). The mutation token is forgeable by any module. `MutationToken`'s constructor is exported and adds the instance to the `MINTED` WeakSet, so `new MutationToken(binding, ttl)` yields a token that `isMutationToken` accepts without a `proceed:true` check (probed). The static test only greps for the string `mintMutationToken`, so `new MutationToken` is invisible to it. Fix: make the constructor module-private (e.g. a non-exported sentinel argument or a factory closure) and extend the static test to forbid `MutationToken(` outside token.ts/pipeline tests.

B3 (per-key mutex, G14). `acquireMutex` loses mutual exclusion after a timeout. When waiter B times out it does `lockTails.delete(key)` because `lockTails.get(key) === tail_B`, even though holder A is still running; waiter C then sees no tail, gets `Promise.resolve()` and enters while A holds the key (probed: A held, B null, C got the lock). Two same-name creates can then overlap, so the post-confirm state recheck is no longer protected. Fix: on timeout, restore the previous tail (`lockTails.set(key, prev-chain)`) instead of deleting, or only delete when `prev` has already resolved. Add a regression test (A holds, B times out, C must also time out).

## Non-blocking (fix before the lock/delete slices)
N1. Branch is 6 commits behind origin/main and conflicts in `package.json` (`test:unit` line). Rebase and re-run before merge.
N2. `client.ts` allows an `unknown` non-GET when the caller passes `mutating:true`. Today no caller passes an ELIAS or user-controlled path, but encoded/near variants of ELIAS or Tier C paths (`/api/v1/certificates%2Fsigning`, `/containers/x/signingKey`, `/API/V1/Containers/Import`, trailing slash) classify `unknown` and would pass for such a caller. Harden: refuse (even with `mutating:true`) any non-GET whose lower-cased, decoded path starts with `/api/v1/(containers|images|epms|files|solver|certificates|lock|heartbeat|ui/unregister)` unless it matches an op. Add the variants to the optable test.
N3. Scrubber keeps any lower-case letters-only (or `a-b` hyphenated lower-case) path segment verbatim, so real container/image names such as `production` or `uc-elux` can land in a fixture path template (probed: `/api/v1/images/uc-elux/some-image/x`). Names are not secrets, but C13 says allow-list extraction; use a vocabulary allow-list of known path words instead. Also `containers/x/signingKey` and the encoded `Certificates%2Fsigning` are not skipped as Tier C (they emit shape-only contracts, no values); skip them for consistency.
N4. `src/elias/fixture-scrub.ts` has `Array<Record<string, any>>` with no comment (DoD: no `any` without a comment).
N5. G6 container-list read failure is audited with gate `validation`; a distinct gate (`conflict`/`read`) would make triage easier. 4xx 408/429 are classed `failed` rather than `unknown`/retry-safe (acceptable, document it).
N6. `ContainerName` regex allows Windows reserved names (`CON`, `NUL`) and a trailing dot; server limits are Open Question Q7, so decide before the tool is registered.
N7. Dry-run writes both a legacy `auditLog` row (from `checkMutationAllowed`) and an ELIAS plan row for the same op (duplicate rows, harmless).
